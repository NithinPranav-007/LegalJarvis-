## 1. Description & Scope
Implemented the end-to-end lexical search capability and the initial frontend vertical slice:
1. **Backend Retrieval Engine (`backend/app/retrieval/lexical.py`)**:
   - Dual-mode lexical search: PostgreSQL Full-Text Search (`to_tsvector` / `plainto_tsquery` / `ts_rank_cd`) in production environments; deterministic `BM25Plus` in-memory fallback for offline test suites and SQLite.
   - Dynamic snippet extraction (`make_snippet`) around query tokens with context boundaries.
   - Provenance attribution preservation adhering to CC-BY-4.0 requirements.
2. **API Layer (`backend/app/schemas/search.py`, `backend/app/api/search.py`, `backend/app/main.py`)**:
   - Pydantic models for `SearchRequest`, `SearchItem`, and `SearchResponse`.
   - Validations: minimum query length (2 chars), pagination limit (1..100), offset bounds.
   - Mounted at `POST /v1/search`.
3. **Frontend Initial Slice (`frontend/src/pages/Search.tsx`, `App.tsx`, `main.tsx`)**:
   - Accessible search input with instant query firing and keyboard support.
   - Court filtering (Supreme Court, High Courts) and year range controls.
   - Results listing displaying judgment title, court, neutral citation, paragraph anchor (`[Para X]`), highlighted snippet, relevance score, and data source attribution note.
4. **Verification & Testing (`backend/tests/api/test_search.py`)**:
   - Integration test verifying search results on real-style Indian judgment fixtures (`Eldeco Housing and Industries Ltd v. Ashok Vidyarthi`, `2023 INSC 1043`).
   - Query validation failure test (rejecting queries < 2 chars with HTTP 422).
